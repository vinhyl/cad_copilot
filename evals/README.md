# evals/ — Prompt 评测基准集（ADR-0002 D9 评测飞轮）

> 状态：骨架（2026-08-19 建立）。资产收集从现在开始，随日常开发积累；
> 目标 30–50 条团队真实指令后启动批量评测。数据边界：R10 已阶段性
> 批准云端 LLM（覆盖日常使用与本评测集）。

## 目录

- `instructions.yaml` — 指令集本体（逐条三层标注，见下）

## 每条指令的三层标注（缺一不可）

| 层 | 字段 | 说明 |
|---|---|---|
| 意图 | `instruction` / `target` | 用户原话（大白话，不要改写）+ 目标对象（哪个零件/特征） |
| 行为 | `golden_trajectory` | 期望的 MCP 工具调用序列（工具名 + 关键参数） |
| 结果 | `assertions` | 几何验收断言（孔径 M8→M10、体积变化范围等，确定性可验） |

## 指令来源与状态流转

```
draft（只记原话，随手收集）
  -> annotated（补全三层标注）
  -> verified（几何断言在当前代码上实跑通过）
```

- **来源优先级**：团队真实工作中说出/想出的指令 > 从设想文档改写的示例。
  示例指令（`source: example`）不计入 30–50 条目标数。
- **收集纪律**：宁可记下来不标注（draft），也不要事后凭记忆补造。

## 评测运行（待 Phase A 后建设，先记录设计）

- runner：批量喂指令给 Agent（WorkBuddy + cad-engine MCP server），记录
  实际调用轨迹，跑 `assertions`，产出四层指标（意图命中 / 工具选择 /
  参数正确 / 端到端）。
- 确定性：固定模型版本 + 温度 + 响应缓存；LLM 调用不进全量 CI。
- 达标门槛（D9）：高确定性 ≥95% 固化为 UI 控件；中确定性 ~90% 固化为
  方案卡 + 二次确认；不达标回炉改 prompt / 工具 docstring 契约。

## 黄金轨迹书写约定

- 工具名与 `cad_mcp_server.py` 的 `@mcp.tool` 保持一致；
- 参数写"语义值"而非精确数值时可标注 `approx: true`，runner 允许容差；
- 轨迹表达**正确行为**，与具体模型无关——先标注不白做（R10 讨论）。
